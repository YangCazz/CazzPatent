# 专利数值泛化规范

- **规则ID**: rule-007
- **严重级别**: important
- **领域**: 通用
- **来源**: 提案6-1/6-2/7-1/7-2 v1-review-pass
- **添加日期**: 2026-07-29

## 背景

在提案6-1/6-2/7-1/7-2 v1 的 Stage 5 审核中，四份交底书均在 2.3 技术效果和四、具体实施方式（实施例）中包含了大量具体的性能数值（TRE均值、mm值、Dice系数、百分比对比、推理秒数、训练轮次、GPU型号、RAM大小等）。专利交底书应使用定性描述而非限定具体数值，避免不当限制保护范围。

## 规则内容

### 需要泛化的数值类型

| 数值类型 | 示例 | 替换为 |
|---------|------|--------|
| 配准精度 | "TRE 均值 2.1mm" | "配准精度有显著改善" |
| 百分比对比 | "提升 43%"、"降低 18%" | "有显著提升/降低" |
| 数量级对比 | "降低了约两个数量级" | "有数量级改善" |
| 推理耗时 | "耗时 156ms"、"118ms" | "在毫秒量级"或"满足实时性" |
| 硬件配置 | "RTX 4060 8GB" | 删除或仅说"在GPU上并行" |
| 训练轮次 | "5-10 轮"、"300 epochs" | "有限轮/若干轮" |
| 影像尺寸 | "512x512x300" | "典型腹部CT容积影像" |
| 搜索窗半径 | "半径 40mm" | "适当搜索窗半径" |
| 关键点数量 | "N=782" | "适当数量的关键点" |
| 收敛容差 | "10^{-5}" | "适当收敛精度" |

### 可以保留的数值

- 数学公式中的序号（如式(1)、(2)）
- 抽象的数量级说明（如"降低约4个数量级"——仅说明相对关系）
- 维度/层数等架构性参数（如"L=4层 EdgeConv"）
- 本文提出的方法参数符号（不赋具体值）

## 检查范围

重点检查 2.3 技术效果和四、具体实施方式。2.2 方法类中的公式推导可保留数学符号和架构参数。

## 检查方法

搜索以下模式：`mm|ms|秒|轮|%|倍|RTX|Intel|epochs|batch|GB RAM|Dice.*\d+\.\d+|TRE.*\d+\.\d+`
